%
%  GOTCHA 1 -- no blank lines inside the \begin{tikzpicture}[...] option list.
%  A blank line is a \par, and TeX will not tolerate one while it is still
%  scanning the optional argument. It fails with "Paragraph ended before
%  \tikz@picture was complete" and then every \node / \draw below reports as an
%  undefined control sequence, which hides the real cause. Use a lone % to
%  separate style blocks instead.
%
%  GOTCHA 2 -- node sizes are absolute (cm) but positions are in grid units of
%  0.78cm, so the two must be kept in step by hand:
%
%      stage box    2.05cm wide  = 2.628 units  (half-width 1.314)
%      column pitch 3.00 units                  -> 0.372 units of clear space
%      lane height  2.00 units, pitch 2.15      -> 0.15 units between lanes
%
%  Change the box width and the column pitch must change with it, or boxes
%  silently overlap their neighbours and the lane labels.
%
%  GOTCHA 3 -- (A |- B) takes x from A and y from B. Only B's y is read, so
%  writing (porig.north |- 6.20,13.80) silently ignores the 6.20.
%
%  Each lane reserves a 0.6-unit header strip at its top for its label; boxes
%  hang 1.25 units below the lane top to clear it. Rotated labels do not work:
%  "Ground cover" set sideways is taller than a lane.
%
%  Routing is orthogonal throughout. Each panorama variant emits ONE line from
%  its own east edge into its own distribution spine, and the spine is where it
%  fans out to that variant's lanes -- so the diagram still shows which variant
%  feeds which lane, which the caption and section 3.3 both rely on. Keep every
%  spine x above 4.55 or it cuts back through the panorama boxes.
% =============================================================================

% One distribution spine per panorama variant, in the gutter between the group
% box (right edge 4.55) and the lanes (left edge 5.90). Each variant emits a
% single line from its own east edge; the spine is where it fans out. Keep all
% three above 4.55 or they cut back through the panorama boxes.
%
% Ordering is psky / pterr / porig, left to right, which costs exactly one
% right-angle crossing: the original's stub crosses the object-removed
% panorama's spine. One is the minimum here. That spine has to reach up
% from its own exit (6.625) to Terrain, so it spans the original's exit height
% (7.775) whichever side it sits on.
%
% This is sensitive to the lane order. Grouping each variant's destinations
% contiguously is what keeps it at one; the earlier Terrain/Objects/Ground/
% Water/Sky/Motion order interleaved them and cost three.
\def\spinesky{4.75}
\def\spineterr{5.05}
\def\spineorig{5.35}

% Collector trunk, between the lane right edge (14.95) and asm.west (15.61).
\def\xbus{15.20}

% Lane slots, top to bottom, are fixed at 11.75 / 9.60 / 7.45 / 5.30 / 3.15 /
% 1.00 (pitch 2.15). To reorder the tracks, permute ONLY the six assignments
% below: the lane rectangles, the labels and all routing are derived from them.
% Each track keeps its own colour, so the colours travel with the reordering.
\def\yterrain{11.75}
\def\ywater{9.60}
\def\yobjects{7.45}
\def\yground{5.30}
\def\ymotion{3.15}
\def\ysky{1.00}

% Extreme slots. These are positions, not tracks, so they do NOT change when
% the six assignments above are permuted.
\def\ylanetop{11.75}
\def\ylanebottom{1.00}
